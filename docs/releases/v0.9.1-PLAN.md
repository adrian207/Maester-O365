# Version 0.9.1 Release Plan

**Author:** Adrian Johnson <adrian207@gmail.com>  
**Target Release Date:** November 30, 2025 (4 weeks)  
**Status:** Planning  
**Type:** Patch Release (Bug fixes + Stability)

---

## Release Overview

Version 0.9.1 is a **stability and quality release** focused on addressing feedback from v0.9.0, fixing bugs, and improving the overall user experience. This release prepares the framework for production readiness in v1.0.0.

---

## Goals & Success Criteria

### Primary Goals

1. **Address Community Feedback**
   - Respond to all critical issues from v0.9.0
   - Implement high-priority feature requests
   - Improve documentation based on user questions

2. **Bug Fixes**
   - Fix all critical bugs (P0)
   - Fix all high-priority bugs (P1)
   - Address medium-priority bugs (P2) as time permits

3. **Stability Improvements**
   - Enhance error handling
   - Improve logging and diagnostics
   - Add health check endpoints
   - Better timeout handling

4. **Documentation Improvements**
   - Fix documentation errors
   - Add missing examples
   - Improve troubleshooting guides
   - Add video tutorials (optional)

### Success Criteria

- [ ] Zero P0 (critical) bugs remaining
- [ ] < 5 P1 (high) bugs remaining
- [ ] 95% test pass rate

- [ ] Documentation completeness > 95%

## Planned Features & Improvements

### 1. Bug Fixes (High Priority)

#### Critical Issues (P0)
- [ ] **Issue #1**: Docker Compose fails on Windows with volume mount permissions
  - **Impact**: Blocks Windows users
  - **Fix**: Update docker-compose.yml with proper Windows paths
  - **Estimate**: 2 hours

- [ ] **Issue #2**: Workload Identity Federation setup unclear for vSphere
  - **Impact**: vSphere users cannot authenticate
  - **Fix**: Add detailed OIDC setup guide
  - **Estimate**: 4 hours

- [ ] **Issue #3**: Remediation engine crashes on certain policy configurations
  - **Impact**: Remediation unusable for affected policies
  - **Fix**: Add validation and error handling
  - **Estimate**: 8 hours

#### High Priority Issues (P1)
- [ ] **Issue #4**: Report server slow with > 1000 test results
  - **Impact**: Poor performance for large tenants
  - **Fix**: Add pagination and indexing
  - **Estimate**: 6 hours

- [ ] **Issue #5**: Terraform modules missing required variables
  - **Impact**: Deployment failures
  - **Fix**: Add validation and defaults
  - **Estimate**: 4 hours

- [ ] **Issue #6**: Notifications not sent if SMTP server unreachable
  - **Impact**: Silent failures in notifications
  - **Fix**: Add retry logic and fallback
  - **Estimate**: 4 hours

- [ ] **Issue #7**: Memory leak in long-running test executions
  - **Impact**: Crashes after extended use
  - **Fix**: Profile and fix PowerShell memory issues
  - **Estimate**: 8 hours

- [ ] **Issue #8**: CI/CD pipeline fails on pull requests from forks
  - **Impact**: External contributors blocked
  - **Fix**: Update GitHub Actions workflow
  - **Estimate**: 2 hours

## Risk Assessment

### High Risk Items
1. **Memory leak fix** - Complex, requires thorough testing
   - **Mitigation**: Extensive profiling, staged rollout
   
2. **Performance optimizations** - May introduce regressions
   - **Mitigation**: Comprehensive benchmarking, A/B testing

3. **Authentication changes** - Could break existing setups
   - **Mitigation**: Backward compatibility, clear migration docs

### Medium Risk Items
1. **Database schema changes** - Requires migration
   - **Mitigation**: Automatic migration scripts, backups

2. **API changes** - Could break integrations
   - **Mitigation**: Versioned APIs, deprecation warnings

### Low Risk Items
1. Documentation updates
2. UI improvements
3. Error message improvements
4. Logging enhancements
